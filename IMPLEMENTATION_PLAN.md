# Genesis Agents — Exhaustive Validation Implementation Plan

Source requirement: `CatoGensisAgentBuild.md` (also committed in the Cato repo — this is a joint
Cato+Genesis program). Executed via `continuous-build-verify` in LOOP-ONLY mode; one task below =
one `ralph-wiggum-loop` build + one `truth-fix-loop` audit before advancing.

Ground truth for every task below comes from a live inventory pass (2026-08-04): a real
`GET /agents` call against `https://swarmsync-agents.onrender.com` returned all 57 live slugs;
`skill_bundles/*.json` (24 files) were read individually; `runtime/tool_policy.py`,
`bundle_loader.py`, `eval/genesis_client.py`, and `eval/datasets/*.jsonl` were cross-referenced
against them. "100% tested" means every row in the resulting agent/tool/capability matrix has a
test and a verdict — not that every future defect is impossible.

**Non-negotiables carried into every task:**
- No agent may return apparent success when no tool ran, the tool failed, the operation is
  pending, the result is unverified, a fallback persona answered instead, or evidence is absent.
- `testContext`/`live_test`/persona-only results are labeled separately and never counted as
  full-agent (AgentRuntime + real tool dispatch) verification.
- A capability that cannot be made safe or reliable gets disabled and removed from the advertised
  capability inventory — not silently left broken.
- Guarded finance/deploy agents (`genesis_deploy_x402`, `genesis_finance_x402`,
  `genesis_billing_x402`, `genesis_commerce_x402`) are never invoked in real/full mode by any task
  below — mocked/guard-proof only.

## Phase B — Test-harness infrastructure (needed before full-matrix execution)

- [ ] Build `docs/validation/agent-inventory.json`: a generated (not hand-written) machine-readable manifest enumerating all 57 live slugs and all 24 skill bundles, each with slug, purpose, declared capabilities, allowed tools, prohibited tools, risk classification (safe / guarded-finance / guarded-deploy / other), live-testable Y/N, mock-required Y/N, and current eval-coverage status. Generation script must call the live `GET /agents` endpoint and read `skill_bundles/*.json` directly rather than hardcoding the list, so it stays correct as bundles change.
- [ ] Extend the eval harness with async job-polling support: `genesis_builder_x402`, `genesis_research_x402`, `genesis_deploy_x402`, `genesis_qa_x402`, and `genesis_meta_x402` all use `job_mode: "async"` and currently only the initial `job_id`/`poll_url` envelope is captured, never the actual completed result. Add `GET /agents/jobs/{job_id}` polling (with a sane timeout and backoff) to the target adapter so these five agents' real output can be scored, not just their envelope.
- [ ] Build a deterministic-evaluators module (`eval/deterministic.py` or similar) covering every category from the required test matrix that can be checked mechanically rather than by LLM judge: structured-output/schema compliance, correct tool selection given the request, refusal-to-fabricate-tool-results, generic-fallback prevention (the request used a slug that IS in `AGENT_PERSONAS`/`skill_bundles` and got a matching, non-fabricated persona back — not the `main.py:1690-1695` fallback), cross-agent routing correctness, cost/latency-limit enforcement, retry/idempotency behavior on duplicate requests. Each evaluator returns a pass/fail plus the concrete evidence it checked, not a vibe.
- [ ] Build `docs/validation/capability-test-matrix.json`: a generated cross-reference of every agent (from Phase B's inventory) against every applicable category from the 30-category test matrix in `CatoGensisAgentBuild.md` Part 2, with current status (not yet run / pass / fail / guarded / mocked) per cell. This becomes the tracking artifact Phase C fills in.

## Phase C — Full-matrix test execution (grouped by risk tier, not one task per agent, to keep this tractable — but every agent must appear in exactly one group's results)

- [ ] Generate and run the full applicable test suite (all 30 categories from `CatoGensisAgentBuild.md` Part 2 that apply to a tool-capable agent) for the 20 skill-bundle-backed agents, through the real `AgentRuntime`/tool-dispatch path wherever safe (not `testContext`/`live_test` bypass) — 3 repetitions per nondeterministic scenario, 5 repetitions for any agent touching finance/compliance/security. Record results into `capability-test-matrix.json` and `test-results.json`; any category that cannot safely run live must be explicitly labeled mocked/guarded, never silently skipped.
- [ ] Generate and run the applicable subset of the 30-category matrix (persona/domain behavior, instruction-following, factual grounding, unknown-information handling, ambiguous/contradictory requests, structured-output compliance, long-context behavior, prompt injection, indirect prompt injection, out-of-authority requests, secret-exfiltration attempts — the categories that make sense for a persona with zero tools) for all 36 persona-only agents (`AGENT_PERSONAS` entries with no matching skill bundle), 3 repetitions each. Record into the same matrix/results files.
- [ ] Generate and run guarded-path-only tests (authorization/denial/sandbox/mocked execution paths — never real financial, payment, or deployment actions) for `genesis_deploy_x402`, `genesis_finance_x402`, `genesis_billing_x402`, and `genesis_commerce_x402`, 5 repetitions each, proving each one correctly refuses or sandboxes every dangerous real-mode request while still answering safely in guarded/mock mode.
- [ ] Run the security/injection/exfiltration/authority-boundary categories (prompt injection, indirect prompt injection, requests outside the agent's authority, secret-exfiltration attempts) as a dedicated cross-cutting pass across every reachable agent (all 57), since these apply uniformly regardless of tool access — a persona-only agent can still leak a system prompt or comply with an out-of-scope request even with no tools to misuse.
